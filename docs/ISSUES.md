# 问题日志

## BTT-001：驻留播放器退化为小窗布局

- 日期：2026-09-13
- 状态：已解决
- 现象或修改背景：向下滚动后只保留了缩小的视频区域，宽屏模式被错误压缩，弹幕发送栏和观看人数等完整播放器区域不可见。
- 原因分析：旧实现使用 `#playerWrap` 内占位元素的宽度计算播放器尺寸；宽屏时该父容器仍为左栏宽度，而完整播放器会横跨两栏。第一次修复又仅把 `data-screen` 从 `mini` 改回页面模式，没有触发 B 站播放器内部的退出小窗流程；真实页面仍保留小窗遮罩，并以内联 `display: none` 隐藏弹幕发送区域。
- 解决方案：以 `#bilibili-player` 的完整实际尺寸作为驻留基准；检测到 `mini` 后点击播放器原生关闭小窗控件，让 B 站自身恢复 `normal` 或 `wide` 的完整内部状态，再接管外层播放器进行顶部驻留。
- 验证方式：运行布局单元测试，并在模拟真实小窗内联样式、独立小窗遮罩和原生关闭按钮的 DOM 测试页中，确认插件实际触发原生退出动作，普通/宽屏模式下观看人数和弹幕发送栏保持可见。
- 相关文件：`src/content/sticky-player.js`、`src/content/sticky-player.css`、`src/shared/sticky-layout.js`、`test/fixtures/sticky-player.html`、`test/sticky-layout.test.cjs`

## BTT-002：驻留播放器遮挡顶部导航栏

- 日期：2026-09-13
- 状态：已解决
- 现象或修改背景：开启播放器驻留并向下滚动后，B 站顶部导航栏看起来消失，无法正常看到或使用。
- 原因分析：旧实现首先存在播放器层级过高、固定在 `top: 0` 的遮挡问题；第一次修复层级后，真实页面仍会偶发只剩 64px 空导航容器。二次排查发现插件在初始化阶段就向 B 站框架管理的播放器节点前插入占位元素，可能打断页面异步挂载和更新时序。
- 解决方案：播放器保持在导航栏下一层，并按可见导航底边计算驻留位置；同时取消初始化阶段的占位节点注入，仅在用户滚动触发驻留后给原生播放器父容器增加最小高度，退出驻留时完整还原。
- 验证方式：运行顶部位置单元测试；在 DOM 测试页确认初始化完成后播放器附近没有新增占位节点，滚动时父容器保留原高度，64px 导航栏保持可见且播放器从其下方开始。
- 相关文件：`src/content/sticky-player.js`、`src/content/sticky-player.css`、`src/shared/settings.js`、`src/shared/sticky-layout.js`、`src/options/options.html`、`test/fixtures/sticky-player.html`

## BTT-003：横屏宽屏播放器缩成居中悬浮框

- 日期：2026-09-15
- 状态：已解决
- 现象或修改背景：在 1920×1080 一类横屏显示器中使用宽屏模式并向下浏览评论时，播放器脱离标题区左边缘，被缩成页面中央的小型悬浮框。
- 原因分析：旧布局只按“播放器最大高度”百分比等比缩放播放器，并在原宽屏区域内居中；横屏页面的原生宽屏播放器横跨左右栏，默认 55% 高度限制会把它压缩到比左侧主内容栏还窄，播放器因此与标题、UP 主信息区失去视觉对齐。
- 解决方案：横屏宽屏驻留时使用标题区宽度作为播放器的响应式最小宽度，并保持播放器左边缘与原生宽屏区域对齐；当视口高度确实不足时仍按剩余高度等比缩小，保证完整播放器不会越出屏幕。
- 验证方式：增加 1824×972 横屏宽屏回归测试，确认 55% 高度配置下播放器不小于 1080px 主内容栏宽度且左侧对齐；另验证低高度视口仍以屏幕底边为硬上限。
- 相关文件：`src/content/sticky-player.js`、`src/shared/sticky-layout.js`、`src/options/options.html`、`README.md`、`test/fixtures/sticky-player.html`、`test/sticky-layout.test.cjs`
